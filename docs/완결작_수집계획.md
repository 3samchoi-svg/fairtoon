# 완결작 카탈로그 수집 계획 (2단계)


작성: 2026-08-11 · 클상무(PM) · 승인: 대표님 ("완결작 데이터 수집 계획을 세우고, 하루에 500편씩 진행하자")
선행: `docs/작품확대_계획.md` (1단계 연재작 880편, 2026-08-11 반영 완료)


## 1. 왜 완결작인가


페어툰 큐레이션의 컨셉 자체가 **"완결작이라 마음 편히 정주행할 수 있다"** 이다. 그런데 1단계에서 연재작 880편을 넣고 나니 커버리지가 거꾸로 됐다.

| 구분 | 현재 편수 |
|------|-----------|
| 완결 | 49편 |
| 연재 | 881편 |

미생·이끼는 검색되는데 같은 급의 완결 명작 수천 편이 안 걸린다. **완결작을 찾는 사람이 오히려 답을 못 받는 상태다.** 2단계는 이 역전을 바로잡는 작업이다.


## 2. 대상 규모 (2026-08-11 실측)


| 플랫폼 | 완결작 수 | 수집 경로 | 확인 |
|--------|-----------|-----------|------|
| 네이버웹툰 | **3,086편** | `api/webtoon/titlelist/finished?page=N` (69페이지 × 45편) | 확인 완료 |
| 카카오웹툰 | **1,216편** | `section/v1/pages/general-completed` (한 번에 전량) | 확인 완료 |
| 카카오페이지 | 미확인 | 요일연재 경로로는 연재작만 나온다. 별도 경로 필요 | 3차로 미룸 |

1·2차 합계 **약 4,300편**. 기존 930편과 중복되는 분은 제외되므로 실제 반영량은 이보다 적다.


## 3. 진행 방식 — 하루 500편


대표님 지시대로 하루 500편씩 나눠 진행한다. 한 번에 몰아서 긁지 않는 이유는 두 가지다.

1. **상대 서버에 대한 예의.** 급하게 긁으면 차단당하고, 그러면 제휴 문의 자체가 우스워진다.
2. **오류를 조기에 발견한다.** 4,300편을 한 번에 넣고 나서 문제를 발견하면 되돌리기가 커진다. 500편 단위면 그 배치만 지우면 된다.

| 회차 | 대상 | 누적 |
|------|------|------|
| 1차 | 네이버 완결 page 1~12 (약 500편) | 500 |
| 2차 | page 13~23 | 1,000 |
| 3차 | page 24~34 | 1,500 |
| 4차 | page 35~46 | 2,000 |
| 5차 | page 47~57 | 2,500 |
| 6차 | page 58~69 (네이버 완료) | 3,086 |
| 7~9차 | 카카오웹툰 완결 1,216편 | 4,302 |
| 10차~ | 카카오페이지 완결 (경로 확보 후) | 미정 |

**하루 1회차.** 네이버는 페이지 번호가 커서 역할을 하므로 중단·재개가 안전하다.


## 4. 회차별 절차


1. **[PM] 수집** — 해당 회차 범위를 수집한다. 작품별 정보 API 한 번으로 장르·줄거리·표지·연령등급이 모두 나온다. 초당 3건 이하.
2. **[PM] 필터** — 아래 5절.
3. **[PM] 중복 제외** — 수집 시점에 Supabase에서 기존 제목 전체를 읽어와 대조한다. 별도 상태 파일을 두지 않는다. DB가 곧 진실이다.
4. **[PM] SQL 생성** — `supabase/1N_finished_batchNN.sql`. 단일 문장 CTE 방식(임시 테이블 금지 — Supabase SQL Editor에서 오류가 난다).
5. **[지호님] 실행** — Supabase SQL Editor.
6. **[PM] 검증** — 편수·링크 누락·라이브 화면. 결과를 대표님께 보고.


## 5. 필터 — 1단계와 동일, 타협하지 않는다


1. **성인물 전면 제외.** 네이버 `adult` 플래그 + `age.type`에 19 포함. 카카오 `adult`·`ageLimit`·`age_grade≥19`.
2. **중복 제외.** 기존 DB 제목과 대조.
3. **딥링크 실검증.** 작품 페이지가 외부 요청에 403을 주면(카카오웹툰에서 실제로 59편 발생) 딥링크 대신 검색 URL로 낮추고 표지도 넣지 않는다. **깨진 링크를 넣느니 검색으로 보내는 편이 낫다.**
4. **요청 속도 제한.** 초당 3건 이하.


## 6. 저장 규칙


- `status = '완결'`
- `is_curated = false` — **명작 큐레이션 49편 화면은 그대로다.** 수집분은 검색으로만 닿는다.
- `sort`는 2000번대부터 부여해 1단계(1000번대)와 구분한다. 회차별 철회가 쉬워진다.
- 표지는 수집분 SQL에 함께 넣는다 (아래 7절).


## 7. 표지 정책


1단계에서는 "제휴 회신 전까지 표지 보류"로 잡았으나, **제휴 문안이 아직 발송 전이므로 실제 편수를 문안에 정확히 적으면 되는 문제**였다. 순서를 거꾸로 잡은 판단이라 정정했다.

- 대표님이 표지 적용(11번 SQL 실행)을 승인하시면, 2단계 수집분도 **표지를 함께 넣는다.**
- 보류를 유지하시면 1단계와 같이 표지는 별도 파일로 분리한다.
- 어느 쪽이든 **철회 스위치는 그대로 살아 있다** — `cover_url`을 비우면 장르 커버로 자동 폴백한다.


## 8. 검증 기준 (회차마다)


1. 수집 편수·필터 제외 편수를 전부 센다. 조용히 누락되는 일이 없게.
2. 딥링크 표본을 실제로 요청해 200을 확인한다. 카카오웹툰은 전수 검증한다.
3. 성인물이 한 건도 섞이지 않았는지 등급 필드로 재확인한다.
4. 라이브 사이트에서 홈 인기 5편·명작 큐레이션 49편이 그대로인지, 검색이 새 작품을 잡는지 확인한다.


## 9. 되돌리는 법


```sql
-- 특정 회차만 취소 (예: 2000~2499번대)
delete from public.works where is_curated = false and sort between 2000 and 2499;
-- 2단계 전체 취소
delete from public.works where is_curated = false and sort >= 2000;
-- work_legal_links는 on delete cascade로 함께 지워진다
```
