### 1. 카카오웹툰 표지 8편이 깨져 있었다 — 대표님이 발견

대표님이 "'지금 인기' 메뉴에 들어갔을 때 '그럴만한 동기'는 이미지가 표시되지 않네"라고 하셨다. **한 편이 아니라 8편이었고, 원인은 우리 스크립트였다.**

**원인** — `scripts/sync_serial.py`가 카카오웹툰 표지 주소를 만들 때 **공유이미지 UUID 하나를 전 작품에 돌려 썼다.** 이 UUID는 작품마다 다른데, 그 값을 쓰는 25편 중 17편은 우연히 맞았고 8편이 404였다.

**어디까지 번졌는지 확인했다**

| 대상 | 방법 | 결과 |
|---|---|---|
| 카카오웹툰 207편 | **전수** HTTP 확인 | 8편 404 + 1편 표지 없음(황녀 스베타, 기존 인지) |
| 레진 4,836 · 카카오페이지 4,293 · 네이버 3,125 · 리디 412 | 표본 150편씩 | 깨짐 0 |

표본 조사에서 카카오페이지 9편이 실패로 찍혔는데, **재시도하니 전부 200이었다. 동시 요청 때문에 난 일시 오류였다.** 이것을 재시도 없이 보고했으면 없는 결함 9건을 만들어 낼 뻔했다.

**조치 두 가지** (`a0b8643`)

1. **데이터** — `supabase/33_kw_covers_fix.md`. 8편의 표지를 각 작품 페이지의 `og:image`로 교체. 8개 주소 전부 200 · image/jpeg · 600×600 확인. **미실행(대표님 대기).**
2. **재발 차단** — `kakaowebtoon_cover(cid)` 신설. 주소를 만든 뒤 **살아 있는지 확인하고 저장**하며, 아니면 빈 값을 줘 장르 그라데이션 fallback으로 넘긴다. 기존 `kakaopage_cover()`와 같은 방식이다. 살아있는 예(미생 818)·죽은 예(그럴만한 동기 4954)로 실제 호출해 확인했다.

**부수 수확** — 카카오웹툰 섹션 API가 `authors[].type`으로 `AUTHOR`(글)·`ILLUSTRATOR`(그림)·`PUBLISHER`를 구분해 준다. 08-31에 브라우저로 작품정보 탭을 긁었던 일을 **API 한 번으로 대체할 수 있다.** 카카오웹툰 203편 글/그림 분리를 자동화할 때 쓸 것.

### 3. 작가 인터뷰 요청 문안 + 질문지 (`output/작가인터뷰_요청메일_질문지.md`)

지호님이 컨설팅업체에서 받은 숙제다 — ①인터뷰 요청 이메일 ②질문 브레인스토밍.

착수 전에 `project-notes/kr/08_크리에이터_인터뷰.md`를 먼저 읽었더니, **형식과 발신자 정체성은 이미 정해져 있고 그 문서 스스로 "질문 리스트가 가장 큰 공백"이라고 적어 두었다.** 그 공백을 메우는 방향으로 썼다.

**담은 것** — 이메일 완성본(변수만 채우면 발송 가능) · DM 축약본 · 승낙 후 안내문 3종 · 질문 21개(6블록) · 서면 10문항 권장 세트 · 진행표 · 묻지 않을 것 · `creator_voices` 칸 매핑 · 체크리스트.

**대표님 지시로 세 번 고쳤다**

| 지시 | 반영 |
|---|---|
| 서면 문항을 10개로 | 5번(불법유통이 작업에 준 영향) · 10번(놓친 질문) 추가. **필수는 3개 유지** — 늘리면 회신율이 떨어진다 |
| 영상 인터뷰 우선으로 | '어떻게 진행되는지'를 영상 요청으로 재작성. 얼굴 비노출·음성만·변조·편집본 사전확인·숏폼 고지를 함께 제시 |
| 줌 말고 대면으로 | 대면 30~40분 요청으로 재작성. 승낙 후 안내문 4-1(대면) 신설, 진행표 조정, 안전 규칙 강화 |

**판단이 들어간 지점**

1. **정산 비율·계약 조건 수치는 질문에서 뺐다.** 비공개 계약이 대부분이라 답하는 순간 작가가 위험을 진다. 아티클 3번에서 그 구간을 "공개되지 않는다"고 쓰고 빗금으로 비워 둔 것과 같은 기준이다. **우리 글에 쓴 기준을 인터뷰에 다르게 적용할 수 없다.**
2. **질문의 무게중심을 '한 회에 며칠이 드는가'에 두었다.** 불법유통을 규탄하는 질문보다 이 사실 하나가 독자를 더 움직인다. 훈계하지 않는다는 사이트 원칙과도 맞는다.
3. **형식은 사다리 세 칸으로 뒀다 — 대면 → 화상 → 서면.** 한 칸만 제시하면 그것이 안 되는 작가는 형식이 아니라 **인터뷰 자체를 거절**한다. 대표님 지시("가급적이면", "만나서")를 우선순위 변경으로 읽고 대안을 남겼다.
4. **작가 명단은 넣지 않았다.** 회신을 가르는 것은 "왜 하필 작가님께" 한 문단인데, 작품을 실제로 읽은 사람만 쓸 수 있다. PM이 임의로 고르면 지호님이 진심으로 쓸 수 없다. 대신 우선순위 기준(SNS 직접 소통 > 완결작 > 피해를 공개적으로 말한 적 있는 작가 > 단체 경유 > 대형 인기작)과 필요 발송량(20~30명)을 적었다.
5. **미성년자 대면 인터뷰의 안전 규칙을 타협 없이 적었다.** 동행 없는 단독 방문 금지 · 공개된 장소만 · 낮 시간 · 가족에게 일정 공유 · 불편하면 중단. 교통비·대관비는 우리 부담으로 명시했다.


### 4. 방문자 통계 기획서 (`docs/방문자통계_기획.md` · 승인 대기)

대표님 요청 — 관리자만 보는 방문자 통계.

**단순 기능 요청이 아니었다.** `Renew/kr/02_KPI.md`를 다시 보니 **측정 수단이 아예 없는 KPI가 네 개**다 — 누적 순방문자 3,000명(10/31) · MAU 1,000명 · **합법 딥링크 아웃바운드 클릭 500회** · 연말 8,000명. 특히 세 번째는 KPI 문서가 "핵심 임팩트 대리지표"로 지정한 항목인데 **지금은 0회인지 5,000회인지 알 방법이 없다.** 정적 사이트라 서버 로그도 오지 않는다.

**3안 비교 후 A안 권고** — 방문자 집계는 Cloudflare Web Analytics(무료·쿠키 없음·도메인이 이미 Cloudflare)에 맡기고, **우리 고유 이벤트(아웃바운드 클릭·검색어)만 자체 수집**해 `/admin`에서 본다. B안(전부 자체)은 봇 필터가 어려워 숫자가 부풀 위험이 있고, C안(GA4)은 쿠키와 사이트 메시지가 충돌한다.

**설계에서 지킨 것** — anon 키로 직접 insert 하지 않고 `sync-serial`과 같은 Edge Function 방식을 쓴다. "쓰기는 관리자만"이라는 RLS 원칙에 통계를 위해 구멍을 내지 않는다. IP·기기 식별값은 저장하지 않는다. 비용 0원.

### 6. 이번 구간의 교훈

1. **표본 조사의 실패는 반드시 재시도한다.** 동시 요청 때문에 난 일시 오류 9건을 결함으로 보고할 뻔했다.
2. **결함 하나를 받으면 같은 원인이 몇 편에 번졌는지부터 센다.** '그럴만한 동기' 한 편만 고쳤으면 나머지 7편은 그대로 남았을 것이다.
3. **고칠 때 데이터와 원인을 같이 고친다.** SQL만 만들었으면 다음 동기화에서 같은 404가 다시 생긴다.
4. **문서를 쓰기 전에 그 주제의 기존 문서를 먼저 읽는다.** `project-notes/08`이 무엇이 비어 있는지 스스로 적어 두어, 중복 없이 공백만 채울 수 있었다.
5. **"기능 추가" 요청 뒤에 KPI가 있는지 본다.** 방문자 통계는 있으면 좋은 기능이 아니라 10월 KPI를 보고할 수 있느냐의 문제였다.
