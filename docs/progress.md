### 4. 리디 링크 144편 보강 — 데이터만 넣으면 화면에 안 보였다

144편에 리디 링크를 붙이는 SQL(27번)을 만들다가, `adoptWorks()`가 **작품당 첫 번째 링크만 쓰고 있음**을 발견했다. 링크를 넣어도 화면에는 아무 변화가 없었을 것이다.

그래서 화면도 함께 고쳤다 — **검색 결과가 한 편일 때**, 그 작품의 정식 링크가 있는 플랫폼 카드를 검색이 아니라 작품 페이지로 보낸다. 여러 편이 걸렸을 때는 어느 작품의 링크인지 알 수 없어 쓰지 않는다.

라이브 검증 결과:

| 검색어 | 결과 |
|---|---|
| 먹는 존재 · 환관제조일기 (2링크 보유) | 리디·레진 **둘 다 "작품 페이지 ↗"** |
| 레바툰 | 레진만 작품 페이지, 나머지 4곳은 검색 |
| 미생 (7편 매칭) | 전부 검색 유지 |

**데이터를 넣기 전에 그 데이터가 화면에 닿는 경로를 확인한다.** 링크만 넣고 "완료"라고 보고하면 대표님은 아무 변화도 못 보실 뻔했다.


### 5. 네이버 중복 5쌍 정리 — 지우면서 검색 경로를 잃지 않게

품질 점검에서 URL 중복 5건이 나왔다. 표기만 다른 같은 작품이 두 번 들어가 있었다(이번 투입과 무관한 기존 것).

- 마음의 소리 / 마음의소리
- 데드데이즈 / 데드데이즈(DEAD DAYS)
- 송곳 / 송곳 1~3부
- 하이브 / 하이브 1~2
- 심연의 하늘 / 심연의 하늘 시즌 1~3

다섯 쌍을 하나씩 열어 대조했다. 남기는 쪽은 전부 명작 큐레이션에 든 정식 표기였고, 순위 데이터에 물린 것도 없었다. **지우는 쪽 제목은 별칭(aliases)으로 옮겨 검색 경로를 살렸다.**

라이브에서 확인했다 — '마음의소리'를 붙여 써도 찾히고, 없어진 제목인 '송곳 1~3부'로 검색해도 살아 있는 '송곳' 한 편이 네이버 작품 페이지 링크와 함께 뜬다.

실행 결과: 12,864 → **12,859편**, URL 중복 5건 → **0건**, 링크 13,003개(리디 268 → 412).
