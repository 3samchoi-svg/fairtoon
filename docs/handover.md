## 7. 직전 대화 컨텍스트 요약 (의사결정 배경)


### 이 구간에서 확정된 판단 — 다시 뒤집지 말 것

1. **동기화는 A(수동 1~2회) 다음 D(Edge Function 자동화).** 전권 키를 GitHub에 두는 안은 배제. 카탈로그가 움직이는 중에 자동 쓰기를 붙이면 잘못된 갱신이 조용히 쌓인다.
2. **클릭 집계는 드랍.** 방문자가 늘어난 뒤 재검토.
3. **명작 큐레이션 49편과 작품 찾아보기는 분리한다.** 추천과 전체 목록은 성격이 달라 섞으면 둘 다 약해진다.
4. **순위 배분 규칙은 화면에 설명하지 않는다.** 단, 데이터가 빠져 있다는 고지는 남긴다.
5. (계승) 표지를 켠다 · 순위를 통합하지 않는다 · 랭킹은 DB가 아니라 리포 파일에 둔다.


### 반복해서 물린 함정

- **Supabase는 한 응답에 1,000행까지만 준다.** 3,017편이면 4페이지다. **편수를 늘릴 때는 반드시 세어서 대조할 것.**
- **Supabase SQL Editor는 문장 단위로 커밋한다.** 임시 테이블 금지, 단일 문장 CTE로 쓸 것.
- **네이버 완결 목록의 page 번호는 안정적 커서가 아니다.** 갱신순이라 뒤로 밀린다. 중복률 상승은 정상이다.
- **카카오웹툰과 카카오페이지는 같은 작품을 함께 서비스한다.** 제목 기준으로 합칠 때 중복이 생긴다.
- **git push가 거부되면 원격의 랭킹 자동 커밋 때문이다.** `git stash -u` → `pull --rebase` → `stash pop` 순서로 처리한다.


### 대표님이 잡아낸 것들

이 구간에서도 네 건을 지적받았다 — 인기 더보기가 완결 명작으로 가는 어긋남, 배분 규칙 문구의 불필요함, 연재작 갱신 정책의 부재, 연재작 목록 메뉴의 부재. **모두 PM이 만들어 놓고 스스로 열어보지 않아 놓친 것들이다. 보고 전에 화면을 직접 열고, 만든 기능의 링크를 눌러볼 것.**
