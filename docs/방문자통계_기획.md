# 방문자 통계 기획서 (관리자 전용)

작성: 2026-09-02 · 클상무(PM) · **승인 대기 초안**
요청: 대표님 — "웹페이지 방문자 통계를 관리자만 접근할 수 있는 툴이나 메뉴로 확인할 수 있게"


## 1. 왜 지금 필요한가 — 없으면 KPI를 보고할 수 없다

`Renew/kr/02_KPI.md`가 요구하는 지표 중 **측정 수단이 하나도 없는 것**이 다음 네 개다.

| KPI | 목표 | 시점 | 현재 측정 수단 |
|---|---|---|---|
| 누적 순방문자 | 3,000명 | 10/31 | **없음** |
| 월간 활성 사용자(MAU) | 1,000명 | 10월 | **없음** |
| **합법 플랫폼 딥링크 아웃바운드 클릭** | 500회 | 10/31 | **없음** |
| 누적 순방문자 (연말) | 8,000명 | 12/31 | **없음** |

특히 세 번째가 중요하다. KPI 문서가 **"핵심 임팩트 대리지표"**로 지정한 항목이다 — 불법 감소는 측정 불가이므로 합법 전환을 대신 재기로 한 그 지표다. **지금은 0회인지 5,000회인지 알 방법이 없다.**

사이트는 GitHub Pages에 올라간 정적 페이지라 서버 로그가 우리에게 오지 않는다. 넣지 않으면 앞으로도 계속 모른다.


## 2. 무엇을 재야 하는가 — KPI에서 역산한 최소 목록

| 순위 | 지표 | 쓰이는 곳 |
|---|---|---|
| 1 | **아웃바운드 클릭 수** (작품별 · 플랫폼별 · 일별) | KPI 그룹 2 핵심 대리지표 |
| 2 | 일별·월별 방문자 수, 순방문자 | 누적 순방문자 · MAU |
| 3 | 유입 경로 (검색 / SNS / 직접) | 마케팅 콘텐츠 효과 판단 |
| 4 | 페이지별 조회 (어느 코너를 보는가) | '지금 인기' 편입 같은 판단의 근거 |
| 5 | 검색어 (사이트 내부 검색창에 무엇을 치는가) | 카탈로그 확대 우선순위 |

1번과 5번은 **이 사이트만의 지표**여서 범용 도구로는 온전히 잡히지 않는다. 2~4번은 범용 도구가 우리보다 정확하다.


## 3. 선택지 세 가지

### A안 · 범용 도구 + 자체 이벤트 수집 (권고)

방문자 수는 Cloudflare Web Analytics에 맡기고, **아웃바운드 클릭과 검색어만 우리 DB에 쌓아** `/admin`에서 본다.

- **장점** — 방문자 집계를 직접 만들지 않아 작업이 작다. Cloudflare는 무료이고 **쿠키를 쓰지 않아 동의 배너가 필요 없다**(불법유통 반대를 말하는 사이트가 추적 쿠키를 심는 그림을 피한다). 도메인이 이미 Cloudflare에 있어 계정을 새로 만들 필요가 없다. 핵심 KPI인 아웃바운드 클릭은 우리 DB에 남아 작품별로 쓸 수 있다.
- **단점** — 초기에는 대표님이 **두 곳**을 봐야 한다(Cloudflare 대시보드 + `/admin` 통계 탭). P2에서 한 화면으로 합칠 수 있다.

### B안 · 전부 자체 구축

방문자 집계까지 직접 만들어 `/admin` 한 화면에서 다 본다.

- **장점** — 한 곳에서 끝난다. 데이터가 전부 우리 것이다.
- **단점** — **봇과 사람을 가르는 일이 어렵다.** 크롤러·프리뷰봇이 섞이면 "순방문자 3,000명"이 부풀고, 부풀린 숫자로 KPI를 보고하면 이 프로젝트가 지켜 온 원칙(§5)과 정면으로 어긋난다. 순방문자 판정에 방문자 식별값을 저장해야 해 개인정보 부담도 생긴다. 작업량은 A안의 3~4배.

### C안 · Google Analytics 4

- **장점** — 무료이고 기능이 가장 많다. 유입 경로 분석이 강하다.
- **단점** — 쿠키를 쓰므로 동의 배너 검토가 따라온다. 화면이 무거워 고등학생 1인 운영에 학습 비용이 크다. 무엇보다 **사이트의 주장과 어울리지 않는다** — 창작자 권리와 정당한 대가를 말하는 페이지가 광고 추적 코드를 싣는 것은 설명하기 어렵다.

**PM 권고: A안.** 이유는 하나로 요약된다 — **우리가 잘 만들 수 있는 것(우리 사이트 고유 이벤트)만 만들고, 남이 더 잘하는 것(방문자 집계)은 맡긴다.**


## 4. A안 상세 설계


### P1 — 즉시 (반나절)

**① Cloudflare Web Analytics 스니펫 삽입**
`index.html`에 beacon 한 줄. 방문자·페이지뷰·유입 경로가 Cloudflare 대시보드에 쌓인다.

**② 아웃바운드 클릭 수집 — Edge Function이 받는다**

```
브라우저(navigator.sendBeacon) → Edge Function(track) → Supabase(events 테이블)
```

**anon 키로 직접 insert 하지 않는다.** 지금 RLS 원칙은 "읽기는 공개, 쓰기는 관리자만"이고, 통계를 위해 그 원칙에 구멍을 내면 누구나 아무 행이나 밀어 넣을 수 있게 된다. 대신 이미 검증된 방식을 그대로 쓴다 — **`sync-serial`과 같이 전권 키는 Supabase 안에만 두고, 함수가 받아서 넣는다.**

함수가 하는 일: 봇 UA 걸러내기 → 값 검증(작품 id·플랫폼 키가 실제로 있는 값인지) → insert.

**테이블 `events`** (한 개로 끝낸다)

| 열 | 내용 |
|---|---|
| `id` | 순번 |
| `kind` | `outbound` / `search` |
| `work_id` | 아웃바운드일 때 어느 작품 |
| `platform_key` | 어느 플랫폼으로 나갔나 |
| `term` | 검색어(검색 이벤트일 때) |
| `path` | 어느 화면에서 눌렀나 |
| `created_at` | 시각 |

- RLS — `select`는 `is_admin()`만, `insert` 정책은 **만들지 않는다**(함수의 전권 키만 쓴다).
- **IP·기기 식별값은 저장하지 않는다.** 아웃바운드 클릭은 '몇 번 눌렸나'를 세는 지표이고, 누가 눌렀는지는 필요 없다.

**③ `/admin`에 '통계' 탭**
기존 관리자 로그인(Supabase Auth + `admins`) 뒤에 붙는다. 대표님만 본다.

- 오늘 / 최근 7일 / 30일 아웃바운드 클릭 수, 누적
- **KPI 진척** — 500회 대비 현재 (막대 하나)
- 작품 TOP 20, 플랫폼 분포
- 검색어 TOP 30 (결과가 0편이던 검색어는 따로 표시 → 카탈로그 확대 우선순위)


### P2 — 선택 (반나절)

Cloudflare Analytics API를 Edge Function으로 프록시해 **방문자·MAU까지 `/admin` 한 화면에** 띄운다. API 토큰은 Supabase 시크릿에 둔다(리포는 공개이므로 절대 파일에 넣지 않는다).


### P3 — 선택 (나중)

KPI 그룹 3(태도 변화 설문 · 합법 이용 서약)을 붙일 때 같은 `events` 테이블에 `kind`만 늘려 쓴다. 퀴즈 완료·아티클 완독도 같은 방식.


## 5. 지킬 원칙

1. **부풀리지 않는다.** 봇 필터를 거치고, 숫자 옆에 "beacon 차단 사용자는 빠진다"는 한계를 적는다. 이 사이트는 아티클에서 남의 통계를 그렇게 다뤘다 — 우리 숫자에 다른 기준을 쓸 수 없다.
2. **최소 수집.** IP·기기 식별값·개인정보를 저장하지 않는다. 쿠키를 쓰지 않는다.
3. **RLS 원칙을 훼손하지 않는다.** 쓰기는 여전히 관리자(와 서버)만.
4. **전권 키는 리포에 두지 않는다.** 08월에 세운 원칙 그대로.
5. **정적 사이트를 무겁게 하지 않는다.** beacon은 비동기 1회, 첫 화면 성능(현재 2.6~3.8초)에 영향이 없어야 한다. 도입 후 재실측한다.


## 6. 비용·일정

| 항목 | 비용 |
|---|---|
| Cloudflare Web Analytics | 무료 |
| Supabase Edge Function 1개 추가 | 무료 한도 내(현재 함수 1개 운영 중) |
| `events` 테이블 | 무료 한도 내(월 수백~수천 행 예상) |
| **합계** | **0원** |

- P1 : 반나절. 대표님 손이 필요한 것 — ⓐ Cloudflare 대시보드에서 Web Analytics 켜고 사이트 토큰 받기 ⓑ SQL 1건 실행 ⓒ Edge Function 배포(기존 절차와 동일)
- P2 : 반나절. Cloudflare API 토큰 발급 필요.
