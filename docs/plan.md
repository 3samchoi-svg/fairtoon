- **대상:** 한국 웹툰만.
- **경제학(economics) 접점:** 본 프로젝트는 지호의 대학 지원 passion project이며 희망 전공(잠정 economics)과 접점을 만든다. 불법유통을 무임승차·창작 인센티브·행동경제(넛지) 등 경제학 렌즈로 일관되게 다룬다. 어그리게이터(마찰 제거)는 그 자체로 '행동경제 개입 실험'이 된다. → §6 참조.

### 4.2 검색 (하이브리드 · 넛지 핵심)

**확정(2026-07-26, 대표님): 하이브리드 방식.** 작품 DB 검색과 패스스루를 결합한다. 검색어가 우리 DB에 있으면 실제 작품 카드로 결과를 보여주고, 없으면 플랫폼 검색 버튼으로 폴백한다. "검색하면 결과가 뜬다"는 경험을 살리되, 신작·미수록작은 무한 커버한다.

**동작(2단):**

1. **작품 매칭(상단):** 입력어를 작품 DB에서 부분일치 검색(제목 KO/EN·별칭·작가, 공백·대소문자 무시). 매칭되면 **작품 카드 그리드**로 표시 — 표지·제목·작가·장르 태그·한 줄 소개 + **합법 플랫폼 바로가기 버튼**. (검증된 딥링크가 있으면 딥링크, 없으면 검색 URL로 연결.)
2. **플랫폼 폴백(하단·항상 노출):** 그 아래에 항상 플랫폼별 검색 버튼을 둔다 — **"네이버웹툰에서 찾기 ↗" "카카오페이지에서 찾기 ↗" …** 각 버튼은 해당 플랫폼의 **검색 URL**(예: `.../search?keyword={입력어}`)로 연결. DB에 없는 작품·신작은 이 폴백이 처리하므로 어떤 작품이든 결과가 빈 화면이 되지 않는다.

- 저장 대상 = ① 작품 DB(§5) + ② 플랫폼별 URL 패턴. 플랫폼 URL 패턴은 신작을 자동 커버하고, DB는 '검색하면 결과가 뜨는' 경험과 표지·메타데이터·SEO를 담당.
- 플랫폼 카드에 로고 + 라이트 가격 모델 안내(무료/기다무/유료 일반 설명, 작품별 실시간 아님 명시).
- 트레이드오프(문서화): DB 미수록작은 여전히 플랫폼 검색결과로 보냄(작품 페이지 정확 착지 불가). DB 수록작만 표지·줄거리 등 메타데이터 노출.
- **인식 연결(넛지):** 검색 결과 화면 하단에 "합법으로 보면 창작자에게 보상이 돌아갑니다" 한 줄 + Articles/작가의 목소리 링크.
- URL 패턴은 구현 전 **실측 확정**(스파이크). 패턴은 잘 바뀌지 않지만, 깨질 경우를 대비해 패턴 목록을 단일 JSON으로 분리 관리.
- **무유지보수 보완장치:** DB가 커질수록 링크 최신화 부담이 생기므로 ①월간 링크 점검 ②각 결과 화면의 '문의하기(링크 깨짐 신고)' 동선을 함께 둔다(§5).

- 장르·테마·시대별 모음("합법으로 보는 숨은 명작", "정주행하기 좋은 완결작" 등).

## 5. 검색 데이터 모델 & 동작 (v2.1 — 하이브리드 검색)

**핵심 결정(2026-07-26, 대표님):** 방식 C 하이브리드 + 작품 DB **150~300편**. 공식 API가 없어 실시간 전수 스크레이핑은 여전히 배제하되, **손으로 채운 검색 가능한 작품 DB(150~300편)** 를 두어 "검색하면 결과가 뜨는" 경험을 만든다. DB에 없는 작품은 패스스루가 무한 커버한다. 두 축을 결합한다.

- **① 작품 DB(검색 결과 표시):** 손으로 채운 정적 JSON, 목표 **150~300편**(완결 명작 우선, 인기 연재작 포함 가능).
  - 데이터: `works: [{title, en, aliases:[], cover, author, genres:[], blurb, status, legal_links:[{platform, url, price_tag}]}]`.
  - `en`·`aliases`는 검색 매칭용(영문 제목·줄임말). `url`은 확인된 작품 딥링크 우선, 없으면 검색 URL.
  - 검색: 클라이언트 JS 부분일치(제목 KO/EN·별칭·작가, 공백·대소문자 무시). 서버 불필요, 정적 배포로 동작.
  - 이 DB가 명작 큐레이션(§4.3)의 소스이기도 하다 — 큐레이션 = DB에 큐레이션 플래그/장르 모음을 얹은 뷰. **데이터 1벌을 검색·큐레이션에 공용.**
- **② 검색 패스스루(무한 커버·폴백):** 저장 대상은 **플랫폼별 URL 패턴**뿐.
  - 데이터: `platforms: [{name, logo, search_url_pattern, price_model_note}]` (예: `search_url_pattern: "https://comic.naver.com/search?keyword={q}"`).
  - 동작: 입력어 `{q}`를 URL 인코딩해 패턴에 끼워 넣어 버튼 생성. DB 미수록작·신작을 자동 커버, 사람 손 불필요.
  - 대상 플랫폼: 네이버웹툰 · 카카오페이지 · 카카오웹툰 · 리디 · 레진.
- **결과 화면 조립:** 상단 = DB 매칭 작품 카드(있을 때), 하단 = 항상 플랫폼 폴백 버튼. 매칭 0건이어도 폴백으로 빈 화면 방지.
- **무유지보수 보완장치(DB 확대에 따른 링크 부패 대응):** ①월간 URL 점검 루틴 ②각 결과 화면 '문의하기(링크 깨짐 신고)' 동선 ③변동 큰 필드(실시간 가격)는 담지 않고 플랫폼 단위 라이트 태그로만. 완결작 위주 선정으로 상태 변경 부담 최소화.
- **KPI:** 버튼 클릭 = 아웃바운드 이벤트 기록(전환 대리지표: 합법 플랫폼 이동 클릭 수).
- **폐기:** 실시간 가격·정기 자동 스크레이핑은 범위 밖(무유지보수 원칙). 가격은 플랫폼 단위 일반 안내(라이트 태그)로만.
- **자동화 검토했으나 비채택:** GitHub Actions 크론으로 네이버 비공식 JSON 주간 스크레이핑 → data.json 자동 커밋 방식은 무인 운영이 가능하나, 사이트 구조 변경 시 조용히 깨져 유지보수가 되고 약관 회색지대라 포트폴리오 리스크. → 미채택(필요 시 재검토).


## 6. 콘텐츠 제작 계획 (무엇을 / 어떻게)

> 대표님 중점 지시 ①: "앞으로 어떤 콘텐츠를 어떻게 제작할 것인가."


### 6-0. 경제학(economics) 렌즈 — 콘텐츠 통일 관점

인식 콘텐츠 전반을 지호의 희망 전공(economics)과 접점을 갖도록 **경제학 프레임**으로 일관되게 다룬다. 이는 인식 메시지에 지적 깊이를 주는 동시에 지호의 대학 포트폴리오·에세이 서사("실제 사회문제에 경제학적 사고를 적용하고 개입 도구까지 제작")를 강화한다.

- **무임승차·공공재:** 불법 열람 = 대가 없이 창작물을 소비하는 free-rider 문제. 모두가 그러면 창작이 지속 불가.
- **인센티브 붕괴:** 수익이 없으면 창작 유인이 사라진다 → 장기적으로 볼 작품이 줄어드는 손실.
- **창작자 경제:** MG(최소보장)·수익배분·연재 구조 등 웹툰 산업의 돈의 흐름.
- **행동경제(넛지):** 합법의 '마찰'을 줄이면(검색 패스스루) 사람들의 선택이 바뀐다 — 어그리게이터 자체가 개입 실험.
- **외부효과·시장실패:** 불법유통이 만드는 시장 왜곡, 정보 비대칭.

→ Articles·데이터 시각화·카드뉴스의 주제 선정과 서술을 이 렌즈에 맞춘다.

> **상세 콘텐츠 메뉴 및 수익 카운터(§4.9-B) 스펙 = `docs/경제학콘텐츠_기획.md`** ('경제학으로 읽는 웹툰' 6편 시리즈 + 카운터 산식·정직성 장치, 공개통계 출처 포함).

| 콘텐츠 | 무엇을 | 어떻게 (제작 방식) | 주기 |
|--------|--------|------|------|
| **작가 인터뷰 영상** | 국내 작가 5인, 불법유통 피해·합법의 의미 | 서면 또는 Zoom 20~30분 → 영상 편집 → 사이트 게재 | 11~12월 5건 |
| **인터뷰 숏츠** | 인터뷰 핵심 발언 30~60초 | 영상에서 클립 컷 → 자막 → 9:16 | 인터뷰당 2~3개 |
| **인식 기사** | 불법 원인·작가 경제·사이트 수익구조·MG | 자료조사 + 데이터 시각화(차트) | 출시 5개 → 월 2회 |
| **카드뉴스** | 개인 위험(악성코드·사기) 통계, 사용법 | 캔바 등으로 제작 | 주 1~2개 |
| **숏폼(데모/위험)** | 불법 사이트 위험성, 어그리게이터 사용법 | 화면녹화 + 자막 | 주 1~2개 |
| **데이터 시각화** | 가격·번역 지연·피해 규모 | 공개 데이터 가공 → 차트 | 기사에 포함 |

- **제작 원칙:** 무예산 → 자체 제작(캔바·기본 편집툴) + 공개 데이터. 인터뷰 영상은 YouTube 공개 업로드로 호스팅비 0.
- **재활용 구조:** 인터뷰 1건 → 영상 + 숏츠 N개 + 기사 1편 + 카드뉴스 → 한 소스를 채널별로 다회 활용.
