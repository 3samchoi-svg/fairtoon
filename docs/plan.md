## 1. 개요

Fairtoon = 합법 웹툰 플랫폼을 쉽게 찾게 해 불법 사이트 이용을 줄이는 인식 개선 웹사이트(지호의 대학 지원 passion project, economics 접점).

- **主목적:** 인식 개선 캠페인. 웹페이지는 인식 콘텐츠의 **허브**이며, 검색·디스커버리는 '인식 → 행동' 넛지 장치.
- **대상:** 한국 웹툰, 한국에서 불법 웹툰을 보는 학생.
- **v3 구조 방향 (2026-07-27 확정):**
  - 유저가 보는 화면을 **메뉴별 페이지(목록/상세)** 로 제대로 분리한다.
  - 지금 코드에 하드코딩된 모든 콘텐츠를 **데이터로 분리**하고, **관리자 페이지에서 업로드·수정**할 수 있게 한다.
  - 저장·인증은 **백엔드(Supabase)** 가 담당하고, **화면은 GitHub Pages에 무료 배포**를 유지한다. 동영상은 **유튜브 임베드**.
- **운영 원칙 재조정:** '완전 무유지보수(정적)'는 관리자 기능을 위해 일부 내려놓되, ①무예산(무료 티어) ②동영상=유튜브 ③운영 리스크(백엔드 휴면 등) 대응 장치를 함께 설계해 유지보수 부담을 최소화한다.

## 3. 시스템 아키텍처 (v3 신규)

**"정적 프론트(무료) + 백엔드(무료 티어) + 유튜브(동영상)"** 조합. 각자 잘하는 것을 맡긴다.

```
[사용자 브라우저]
      │  (읽기: 공개 콘텐츠)
      ▼
[프론트엔드]  ── GitHub Pages 무료 호스팅
  · 유저 화면(홈/검색/작품/아티클/작가의 목소리/Stay Safe/About)
  · /admin 관리자 화면 (로그인 필요)
      │  (Supabase JS SDK로 통신)
      ▼
[백엔드]  ── Supabase 무료 티어
  · Database (Postgres)  : 작품·아티클·인터뷰·안전카드·배너 등 콘텐츠
  · Auth                 : 관리자 로그인(팀원 여러 명, 이메일 초대)
  · Storage              : 이미지(표지·기사 이미지) 업로드
  · RLS(행 수준 보안)     : 공개 콘텐츠는 누구나 읽기 / 쓰기는 관리자만

[동영상]  ── YouTube (무료·무제한·CDN)
  · 관리자는 '영상 파일'이 아니라 '유튜브 링크'만 입력 → 사이트에 임베드
```

**왜 이 조합인가 (2026-07-27 대표님 확정 근거):**

- 동영상 용량 문제: 어떤 무료 티어도 동영상 직접 스트리밍엔 부적합 → 유튜브가 정답(A/B 공통). 따라서 백엔드가 저장할 실데이터는 텍스트 + 이미지뿐이며 무료 티어로 충분.
- 관리자 여러 명 로그인·권한 → 백엔드 Auth가 자연스럽다.
- 향후 유저 계정·개인화 기능 가능성(대표님 Q3 "가능성 있음") → 백엔드가 있으면 확장이 열려 있다.

**운영 리스크 & 대응:**

- Supabase 무료 프로젝트는 장기 미사용 시 **휴면**될 수 있음 → ①정기 keep-alive 핑(무료 크론) ②일정 트래픽 확보 후 자연 해소 ③필요 시 저비용 상향. 착수 전 최신 정책 재확인.
- 무료 티어 한도(대략): DB 500MB · Storage 1GB · 트래픽 월 5GB → 텍스트+이미지 규모엔 충분. 이미지 급증 시 무료 이미지 CDN(Cloudinary 등)로 분산.


## 4. 사이트맵 & 유저 화면 구조 (v3 개정)

**헤더(전 페이지 공통):** 로고 · 홈 · 작품 찾기 · 작가의 목소리 · 아티클 · 안전하게 보기 · 소개 · 검색바 · 언어토글

메뉴마다 '목록 페이지'와, 필요한 경우 '상세 페이지'를 둔다. 각 페이지의 콘텐츠 출처(정적/관리자 업로드)를 명시한다.

| # | 페이지 | 유형 | 콘텐츠 출처 | 성격 |
|---|--------|------|------------|------|
| 1 | **홈** | 단일 | 일부 관리자(추천 배너·featured) + 정적 | 인식(主)+넛지 진입 |
| 2 | **작품 찾기** (검색·탐색 통합) | 목록 + 상세 | 관리자(작품 DB) + 플랫폼 폴백 | 넛지 |
| 3 | **작가의 목소리** | 목록 + 상세 | 관리자(인터뷰) | 인식 |
| 4 | **아티클** | 목록 + 상세 | 관리자(기사) | 인식(핵심·SEO) |
| 5 | **안전하게 보기(Stay Safe)** | 단일(탭) | 관리자(안전 카드) | 인식 |
| 6 | **소개(About)** | 단일 | 정적 | 신뢰 |
| — | **취향 테스트** | 단일 | 정적(클라이언트) | 재미·바이럴(§15-A) |
| — | **관리자(/admin)** | 로그인 후 여러 화면 | — | 운영(§6) |

- 기존 '명작 큐레이션(Discover)'과 '검색'은 **'작품 찾기' 하나로 통합**한다: 검색·장르 탐색·큐레이션 모음이 한 데이터(작품 DB)의 서로 다른 뷰.
- **작품 상세 페이지 부활:** 작품 DB가 생기므로 개별 작품 상세(표지·줄거리·작가·합법 플랫폼 링크·유사작)를 제공. DB 미수록작은 검색 폴백이 처리.


## 5. 페이지별 상세 기획


### 5.1 홈

- **상단:** 큰 중앙 검색바("작품명으로 어디서 합법으로 볼지 찾기") → '작품 찾기'로 연결.
- **How Fairtoon works 스트립:** ①찾는다 → ②합법 플랫폼으로 바로 간다 → ③왜 합법인지 안다.
- **인식 콘텐츠 허브(主):** 최신 아티클·작가의 목소리·Stay Safe 진입 블록.
- **추천 배너(관리자):** featured 작품·이벤트·후크 배너를 관리자에서 교체.
- **재미 요소:** 취향 테스트 배너(§15-A) + 창작자 수익 유출 카운터(§15-B).


### 5.2 작품 찾기 (검색 + 탐색, 하이브리드)

**동작(2단):**

1. **작품 매칭(상단):** 입력어를 작품 DB에서 부분일치 검색(제목 KO/EN·별칭·작가, 공백·대소문자 무시) → 매칭 시 **작품 카드**(표지·제목·작가·장르·한 줄 소개 + 합법 플랫폼 바로가기). 카드 클릭 → **작품 상세**.
2. **플랫폼 폴백(하단·항상 노출):** 플랫폼별 검색 버튼(네이버웹툰·카카오페이지·카카오웹툰·리디·레진). DB 미수록작·신작을 무한 커버.

- **탐색 모드:** 검색어가 없을 때는 장르·완결/연재·큐레이션 모음("합법으로 보는 숨은 명작" 등)으로 브라우징.
- **작품 상세 페이지:** 표지·줄거리·작가/작화·장르·연재상태·**합법 플랫폼별 링크(가격 태그)**·유사작·인식 넛지 한 줄.
- **인식 넛지:** 결과·상세 하단에 "합법으로 보면 창작자에게 보상이 돌아갑니다" + 아티클 링크.
- **무유지보수 보완:** 월간 링크 점검 + '링크 깨짐 신고(문의)' 동선.


### 5.3 작가의 목소리

- **목록:** 인터뷰 카드 그리드(작가명·작품·핵심 인용구·썸네일).
- **상세:** 인터뷰 영상(유튜브 임베드) + 숏츠 갤러리 + 인용구 + 요약.
- 출시 시 플레이스홀더(샘플 명시) → 11~12월 실제 인터뷰로 채움(§9).


### 5.4 아티클 (인식·SEO 핵심)

- **목록:** 기사 카드 + 카테고리 필터(경제학 렌즈 분류).
- **상세:** 본문(마크다운/리치 텍스트, 이미지·차트 포함) + 내부 링크(검색·작가의 목소리).
- 출시 5편+ → 월 2회. 상세 콘텐츠 메뉴는 `docs/경제학콘텐츠_기획.md` 참조.


### 5.5 안전하게 보기 (Stay Safe)

- 흔한 위협(악성광고·가짜 업데이트·알림권한 악용), 기기별(아이폰·안드로이드·맥·윈도우) 체크리스트, 노출 시 복구 단계.
- 카드형 콘텐츠는 관리자에서 추가·수정.


### 5.6 소개 (About)

- 미션, 지호의 고등학생 프로젝트 스토리, 데이터 출처·면책, **문의(링크 깨짐 신고) 접점**.


## 6. 관리자 (Admin CMS) 명세 (v3 신규)

`/admin` 경로. **Supabase Auth 로그인(팀원 여러 명, 이메일 초대제)** 후 접근. 비로그인 시 로그인 화면.

**관리 대상 콘텐츠 (대표님 Q1 "전부"):**

| 관리 항목 | 기능(CRUD) | 특이 입력 |
|-----------|-----------|-----------|
| **작품 DB** | 생성/수정/삭제/검색 | 표지 이미지 업로드, 합법 플랫폼 링크 여러 개, 장르 태그, 큐레이션 여부 |
| **아티클** | 생성/수정/삭제/발행토글 | 본문 에디터(마크다운/리치), 대표 이미지 업로드, 카테고리, 발행일 |
| **작가의 목소리** | 생성/수정/삭제 | 유튜브 링크(인터뷰·숏츠), 인용구, 작가 정보 |
| **Stay Safe 카드** | 생성/수정/삭제/정렬 | 기기 분류, 아이콘, 본문 |
| **홈 추천 배너** | 생성/수정/삭제/활성토글/정렬 | 이미지, 링크, 노출 기간 |

**공통 사항:**

- **입력 폼 + 목록 관리** UI. 이미지 = Supabase Storage 업로드(드래그앤드롭). 동영상 = 유튜브 URL 입력만.
- **KO/EN 이중 입력** 필드(제목·본문 등 다국어 콘텐츠).
- **발행 상태**(초안/발행) 구분 → 발행된 것만 사용자 화면에 노출.
- **권한:** 초대된 관리자만 쓰기. 일반 방문자는 읽기만(RLS로 강제).
- **감사 편의:** 생성/수정 시각·작성자 기록.


## 7. 데이터 스키마 (Supabase · 초안)

착수 시 확정하되, 초안은 다음과 같다. (다국어는 `_ko`/`_en` 접미사.)

- **works** (작품): `id, title_ko, title_en, aliases text[], author, art_author, cover_url, genres text[], blurb_ko, blurb_en, status(연재/완결), is_curated bool, curated_note, sort, created_at, created_by`
- **work_legal_links**: `id, work_id fk, platform_key, url, price_tag`
- **platforms**: `id, key, name, logo_url, search_url_pattern, price_note_ko, price_note_en, sort`
- **articles**: `id, slug, category, title_ko, title_en, excerpt_ko, excerpt_en, body_ko, body_en, cover_url, read_time, is_published, published_at, created_by`
- **creator_voices**: `id, creator_name, work, quote_ko, quote_en, interview_youtube_url, shorts jsonb[{youtube_url, caption}], summary_ko, summary_en, is_published`
- **safety_cards**: `id, device, icon, title_ko, title_en, body_ko, body_en, sort`
- **home_banners**: `id, type(featured/hook), title, subtitle, image_url, link, starts_at, ends_at, is_active, sort`
- **RLS 정책:** 모든 콘텐츠 테이블 = `select` 공개(발행분), `insert/update/delete` = 인증된 관리자만.
- 관리자 계정 = Supabase Auth 사용(별도 유저 테이블 최소화, 필요 시 `admin_roles`).


## 8. 검색 동작 (하이브리드 · 백엔드 반영)

- 프론트가 Supabase `works`에서 후보를 조회(제목 KO/EN·별칭·작가 부분일치)해 상단 결과 렌더.
- 미매칭·신작 → `platforms`의 `search_url_pattern`에 입력어를 끼워 폴백 버튼 생성.
- **KPI:** 합법 플랫폼 이동(아웃바운드) 클릭 이벤트 기록 = 전환 대리지표.
- 현재 `index.html`에 구현된 하이브리드 로직(v2.1)을 백엔드 데이터 소스로 옮겨 계승한다.


## 9. 콘텐츠 제작 계획 (무엇을 / 어떻게) — v2.1 계승

> 대표님 중점 지시 ①: "앞으로 어떤 콘텐츠를 어떻게 제작할 것인가."


### 9-0. 경제학(economics) 렌즈 — 콘텐츠 통일 관점

인식 콘텐츠 전반을 지호의 희망 전공(economics)과 접점을 갖도록 **경제학 프레임**으로 일관되게 다룬다.

- **무임승차·공공재** / **인센티브 붕괴** / **창작자 경제(MG·수익배분)** / **행동경제(넛지·마찰)** / **외부효과·시장실패**.

## 11. 기술 스택 & 배포 (v3 개정)

- **프론트엔드:** 정적 SPA를 GitHub Pages에 무료 배포(현행 유지). 관리자 CMS 화면 포함. 프레임워크는 착수 스파이크에서 확정(현행 vanilla 유지 최소화 vs 경량 프레임워크 도입 — 관리자 폼·라우팅 유지보수성 기준으로 결정). 
- **백엔드:** Supabase(무료) — DB·Auth·Storage. 프론트는 Supabase JS SDK로 통신.
- **동영상:** YouTube 공개 임베드(파일 미저장). 숏츠는 각 플랫폼 네이티브 업로드.
- **SEO(아티클) 검토 항목:** 클라이언트 렌더 SPA는 SEO에 불리 → 필요 시 아티클만 정적 프리렌더(빌드) 옵션 검토(스파이크).
- **배포:** 단계별 push → 라이브 확인(https://3samchoi-svg.github.io/fairtoon/). 비밀키(Supabase anon key)는 공개 가능 범위만 노출, 쓰기 권한은 RLS로 방어.
